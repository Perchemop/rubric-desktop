# Rubric v0.2 – Discovery & Design Brief

Date: 2026-10-24
Status: Discovery
Owner: Rubric Dev

## 1. Working title & purpose
Rubric v0.2 – Reviewer/Auditor enhancements
Continue the free, cross-platform PDF markup and measurement desktop tool. Focus on reviewer productivity and auditability for auditors and technical reviewers.

## 2. Primary user & problem
Primary user: reviewers and auditors who need to:
- Apply consistent markups at scale
- Track who did what and when for audit trails
- Organize markups by status, subject, layer
- Compare versions of a document to see what changed

Problem: v0.1 provides basic markup, measurement, project persistence, history, and packaging. Reviewers need better organization and traceability without moving to a cloud product.

## 3. Scope – in / out for first major version
In scope – capability level:
- Markups List with filter, sort, group by status/subject/author/layer
- Status workflow with clear state transitions and audit metadata
- Markup reuse / styles: save favorite markup appearance and reapply
- Version comparison at markup level: diff two `.rubric.json` projects and highlight added/removed/changed markups
- Improved keyboard navigation and shortcuts discoverability
- Dark theme polish and contrast verification

Out of scope for v0.2:
- Cloud sync, real-time collaboration, account-based workflows
- OCR – research only, heavy native deps and privacy considerations
- Real-time Studio Sessions style collaboration
- Plugin ecosystem

## 4. Inspiration – capability level only
- Bluebeam Studio: Markups List, audit trail, status workflow, layer/legend organization, markup reuse. Source: docs/research/bluebeam-studio-capabilities.md
- Adobe Acrobat: Document comparison report, OCR detection for scanned PDFs, markup toolset breadth. Source: docs/research/adobe-acrobat-capabilities.md

Clean-room: no proprietary text, UI copy, icons, or trade dress reused. Only capability concepts.

## 5. Research findings summary
- Markups List with metadata is a standard reviewer expectation for traceability.
- Version comparison is commonly requested; Acrobat implements page-level diff with optional OCR.
- OCR is widely available in commercial tools but introduces privacy and dependency weight; Rubric local-first stance suggests deferring.

## 6. Design principles
- Local-first, no telemetry
- Domain-first types, pure Rust, headless testable
- Keyboard first, visible focus, screen-reader semantics maintained
- No unbounded local builds; CI is the verifier

## 7. Open questions
