# Task — v0.2-04 persistence hardening (F-502, F-507)

**Requirement IDs:** F-502 (autosave), F-507 (project schema versioning)
**Traceability:** R-S-013 (persistence)
**Phase:** Chat → Task
**Status:** Planned

## Goal

Close the two remaining persistence gaps in the v0.2 line: actually run the
existing autosave stub from the app loop, and stamp every project file with a
`schema_version` that is checked on load so a newer file is refused instead of
mis-read.

## Behaviour

### Autosave (F-502)

- `File → Auto-save` exposes an enable checkbox and an interval submenu
  (30 s / 1 min / 2 min / 5 min / 10 min). The choice is `Settings.auto_save`
  and `Settings.auto_save_interval_secs`, so it travels with the project file.
- When auto-save is on and the project has unsaved changes, the app writes an
  autosave **at most once per interval** while a repaint loop is running. The
  interval is clamped to at least 5 seconds.
- The autosave is written next to the open project (`<name>.autosave.rubric.json`)
  when the session knows a path, and into the app data directory otherwise.
- Success reports `Autosaved: <path>` in the status bar and clears the unsaved
  flag. Failure reports `Autosave failed: …` and keeps the flag set so the next
  interval retries. The write is small and synchronous on the UI thread (no
  background thread in this slice), rate-limited to one attempt per interval.
- Only committed project changes count as unsaved: undo/redo snapshots and
  canvas/inspector commits. Selection and other session-only state do not.

### Schema versioning (F-507)

- `Project` carries `schema_version`; the current value is `CURRENT_SCHEMA_VERSION`
  (1). It is written on every save (including autosave) and is part of history.
- Files saved before the field existed have no `schema_version` and load as the
  current version.
- `load_project` validates the field and refuses a version outside
  `1..=CURRENT_SCHEMA_VERSION` with a clear `DataError::UnsupportedSchema`; a
  future file is never partially loaded.
- The check lives in one place so a later migration step has a single seam.

## Files likely touched

- `apps/rubric/src/domain/project.rs` — `CURRENT_SCHEMA_VERSION`,
  `Project.schema_version`, auto-save interval presets + label, tests.
- `apps/rubric/src/data/error.rs` — `UnsupportedSchema` variant.
- `apps/rubric/src/data/store.rs` — schema validation on load, autosave path +
  due helper, autosave signature, tests.
- `apps/rubric/src/ui/app.rs` — unsaved flag wiring, autosave timer + status,
  File → Auto-save menu.
- `apps/rubric/tests/domain_tests.rs` — schema save/load integration tests.
- Tracking files: `IMPLEMENTATION_PLAN.md`, `ROADMAP.md`, `CHANGELOG.md`,
  `PROGRESS.md`, `REQUIREMENTS_TRACEABILITY.md`, `docs/spec/README.md`,
  `docs/parity.md`, `docs/data-model.md`.

## Acceptance criteria

- [ ] Auto-save menu writes `Settings.auto_save` /
      `Settings.auto_save_interval_secs` and those values survive save/load.
- [ ] A dirty project with auto-save on is written once per interval; a clean
      project is never written; the status bar reports the resulting path.
- [ ] A failed autosave keeps the project dirty and reports the error.
- [ ] Autosave path is a sibling of the saved project, or the app data dir when
      there is no path, and is a valid `.rubric.json`.
- [ ] `schema_version` is serialised and defaults to the current version for
      legacy files.
- [ ] `load_project` rejects a newer/unknown schema version without loading it.
- [ ] Domain + data tests cover the version check and the autosave due/path
      rules headlessly.
- [ ] No proprietary material, assets or dependencies introduced.

## Definition of done

The behaviour is implemented, the domain, data and integration tests pass in
GitHub Actions (fmt, clippy `-D warnings`, full tests, release build), the
tracking files record the result, reviewer findings are addressed, and the PR
is merged.

## Out of scope

- An on-open recovery prompt that offers the autosave file; the autosave is a
  valid `.rubric.json` that can be opened manually via File → Open. A recovery
  UI is a separate slice.
- Migrating hypothetical future schema versions; only the check seam is added.
- Exposing `ui_scale` / `show_grid` / `show_measurements` in the new menu.
