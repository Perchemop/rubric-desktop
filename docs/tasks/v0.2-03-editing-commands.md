## Goal

Finish the two open selection-editing commands in the review workflow: copy a
markup's visual style and apply it to other selected markups, and reorder
markups on a page without leaving the canvas.

## Behaviour

### Copy properties (F-114)

- **Copy Properties** captures the visual `MarkupStyle` of exactly one selected
  markup. It works on locked markups because it is read-only.
- **Paste Properties** applies the captured style to every selected markup that
  is not locked. Geometry, page, id, author, subject, review status, comments,
  lock state and measurement are unchanged; `modified` is refreshed.
- A paste is one committed action and pushes one undo snapshot. Locked or
  missing targets are skipped and reported in the status bar.
- The clipboard is session-only UI state. It is intentionally not saved in
  `.rubric.json`.
- Applying a style does not copy review status or lock state. Reusable presets
  that change those fields remain a separate future affordance and must be
  gated explicitly.

### Z-order (F-115)

- **Bring Forward / Send Backward** move exactly one selected markup one place
  later/earlier in paint order among markups on the same page.
- **Bring to Front / Send to Back** move it to the end/start of that page's
  paint order.
- A command at the page boundary is a no-op. Markups on other pages keep their
  relative order and are not moved across the page boundary by the one-step
  commands.
- Locked markups refuse the command. A successful move is one committed action
  and pushes one undo snapshot.

## Acceptance criteria

- [x] Copy/Paste Properties and all four z-order commands appear in the shared
      canvas/inspector context menu and the Edit menu with correct enablement.
- [x] Copy requires exactly one selection; paste requires a captured style and
      at least one selection; z-order requires exactly one selection.
- [x] Paste changes only `MarkupStyle` (plus `modified`) and skips locked
      targets.
- [x] Z-order operates within the selected markup's page and reports boundary
      no-ops without pushing history.
- [x] Locked markups cannot be reordered or restyled; copy still works.
- [x] Domain unit tests cover the style application and z-order invariants.
- [x] Redo is Ctrl+Y, with the hint bar, spec, CHANGELOG and agent guidance
      updated consistently.
- [x] No proprietary material, assets or dependencies introduced.

## Definition of done

The slice is done when the behaviour is implemented, the domain and action
tests pass in GitHub Actions (fmt, clippy `-D warnings`, full tests, release
build), the tracking files record the result, the reviewer findings are
addressed, and the PR is merged.

## Out of scope

- Copying author, subject, status, lock state, comments or geometry.
- Multi-selection z-order ordering.
- A reusable style-preset library UI.
- Keyboard shortcuts for the new copy/z-order commands; the existing
  context/Edit menus are the path.
