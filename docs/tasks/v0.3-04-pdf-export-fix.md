# Task v0.3-04 — PDF export/print fixes (M4/M5)

**Status**: in progress — M4 done; M5 pending an explicit export-scope decision.

## Source

From `docs/audits/v0.2.0-full-audit.md`:

- **M4**: PNG render silently omits the PDF background on failure and still reports success (blank white page exported/printed).
- **M5**: Export/print are view-relative (zoom-scaled, 80 pt margin, themed backdrop), not fixed-DPI or page-cropped — under-specified (open question Q in `docs/assumptions-and-questions.md`).

## Goal

Fix PDF export and print functionality to:
1. Report errors when PDF background rendering fails
2. Implement fixed-DPI/page-cropped export that matches printed output

## Acceptance criteria (DoD)

- [ ] `data/render.rs`: Error handling for PDF background rendering failures
- [ ] Export/print use fixed DPI (300 DPI recommended for print) instead of view-relative
- [ ] Page-cropped output (no margins, no backdrop theme)
- [ ] Honest status messages on success/failure
- [ ] Unit tests for render functions

## Files likely touched

- `apps/rubric/src/data/render.rs` — fixed-DPI rendering
- `apps/rubric/src/data/print.rs` — page-cropped output
- `apps/rubric/src/ui/app.rs` — export/print UI triggers
- `apps/rubric/tests/domain_tests.rs` — render tests

## Implementation approach

1. Add DPI parameter to render functions (default 300 for export)
2. Remove margin/background from render target
3. Add error handling for PDF background load failures
4. Update status messages
5. Add tests

## Progress

- **M4 — done.** `data::render` gained `load_page_background()`, which
  propagates a failure to produce the PDF page background (missing PDF, engine
  error, undecodable PNG) instead of silently exporting/printing a blank page.
  Covered by the `export_background_failure_is_reported` unit test.
- **M5 — pending.** The audit itself marked M5 "under-specified (open question
  Q in `docs/assumptions-and-questions.md`)": export/print are currently
  view-relative (zoom-scaled, 80 pt margin, themed backdrop). Moving to a
  fixed-DPI, page-cropped export changes the product's export semantics, so it
  needs an explicit decision on the DPI and whether markups outside the page
  bounds are clipped, before implementation. Left as a follow-up.

## Definition of Done

- [x] M4: honest error on a failed PDF background (+ test)
- [ ] M5: fixed-DPI / page-cropped export (blocked on the export-scope decision)
- [ ] Tests pass in CI
- [ ] PR opened via `ci.sh`, reviewed, merged
