# Task v0.3-02 — hayro PDF engine adoption (H8 follow-up)

**Status**: planning

## Source
- Audit defect **H8** — `docs/audits/v0.2.0-full-audit.md:28,125-128`: PDFium is a native library; releases must ship a library per platform and a fresh install cannot render PDFs until the user supplies it.
- Research note approved 2026-10-31: `docs/research/hayro-pdf-engine.md` (pure-Rust engine, direction chosen: `hayro` for rendering, `lopdf` for later write support).

## Goal
Replace the PDFium rendering path with a pure-Rust `hayro` rendering path, keeping the existing public API of `apps/rubric/src/data/pdf.rs` unchanged so the UI and domain layers require no changes.

## Acceptance criteria (DoD)
- `apps/rubric/src/data/pdf.rs` exposes the same public functions (`bind_pdfium` → renamed to `bind_pdf_engine` or kept as a façade), `PdfSourceInfo`, `render_page_to_cache`, `render_cache_dir`, with identical signatures where possible.
- Page size probing uses `hayro-syntax`/`hayro` and returns `(width, height)` in PDF points matching the previous PDFium results for the reference corpus.
- Rendering produces PNG bitmaps that are pixel-equivalent (within tolerance) to PDFium output for the corpus of 10 representative PDFs (text, images, vector, rotated pages).
- The native PDFium dependency is optional during this slice: the build compiles without `pdfium-render`; PDFium code paths remain behind a feature flag or compile-time `cfg` and are deleted only after fidelity/corpus tests pass.
- `Cargo.toml` adds `hayro` (pinned exact version), removes `pdfium-render` once the fallback is proven, and `deny.toml` reflects the new licence.
- CI passes (fmt, clippy `-D warnings`, tests, release build, packaging plan) and the personal-data scan is clean.
- Documentation updated: `docs/pdfium.md` → `docs/pdf-engine.md`, `Cargo.lock`, `CHANGELOG.md`, `PROGRESS.md`, `ROADMAP.md`, `REQUIREMENTS_TRACEABILITY.md` (H8 closure).

- H8 recorded as resolved in `docs/audits/v0.2.0-full-audit.md` follow-up and `PROGRESS.md`.
