# Task Brief – v0.2-02 Markups List UI

**Phase:** Chat → Task
**Status:** Implemented in PR #34; reviewer findings addressed
**Requirement IDs:** R-V02-01 Markups List (UI); supports R-V02-02 review metadata
**Depends on:** v0.2-01 domain slice (`MarkupList`, `MarkupListFilter`,
`MarkupListSort`, `MarkupGroupKey`), merged in `59694b2`.

## Goal

Add a real Markups List panel to the desktop app so reviewers can inspect,
filter, sort, group and select markups without hunting on the canvas. The panel
is a thin UI over the already-tested domain model; it must not re-implement
filtering, sorting or grouping.

## Acceptance criteria

- A resizable bottom panel shows the active document's markups.
- Filters: free-text search, status, author, subject and layer (including the
  default layer). Filters are inclusive and built with `MarkupListFilter`.
- Sort: every `MarkupListSort` variant, applied through `MarkupList::sort`.
- Group: none, status, author, subject, layer, kind or page, applied through
  `MarkupList::group` with human layer names.
- Clicking a row selects that markup and switches the canvas to its page;
  selection changes never push an undo snapshot.
- Empty states distinguish: no active document, no markups in the document, and
  no matches for the current filters. A "Clear filters" action exists.
- The panel can be shown/hidden from View → Show Markups List.
- All labels are plain, original strings; no colour-only status signal (the
  status text is always present).
- Accessibility scope: standard egui controls for filters/sort/group/clear and
  no added motion. Full keyboard row traversal and the screen-reader spot
  check are explicitly deferred to F-605 (v0.3); rationale recorded in
  `PROGRESS.md`.
- Pure UI-state mapping and value dedupe helpers have headless unit tests.
- Tracking files, CHANGELOG, ROADMAP and traceability are updated.
