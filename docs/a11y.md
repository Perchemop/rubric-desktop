# Accessibility (spec F-605)

Rubric aims to be usable by keyboard and assistive-technology users as far as
the egui/eframe toolkit allows. This document records the audit and the
remaining, honest limitations.

## Contrast audit (WCAG 2.x)

The contrast maths live in the domain (`src/domain/a11y.rs`): relative
luminance, contrast ratio, and the AA/AAA thresholds. The UI palette audit runs
as a headless unit test (`src/ui/theme.rs::shipped_palettes_meet_wcag_contrast`)
so a palette regression fails CI.

Requirements applied:

| Pair | Level | Result |
|---|---|---|
| Light body text on panel / window / extreme bg | AA normal (≥ 4.5:1) | pass |
| Dark body text on panel / extreme / faint bg | AA normal (≥ 4.5:1) | pass |
| Dark-theme link (Accent 2) on panel | AA normal (≥ 4.5:1) | pass |
| Light/dark text on the accent **selection fill** | AA large (≥ 3:1) | pass |

Body text colour is now set explicitly (`override_text_color`) per theme rather
than inherited from egui defaults, so the audited values are the ones actually
rendered.

### Known, accepted limitation

The brand accent `#E4572E` reaches ~3.7:1 against white — enough for large text
and UI components (AA large) but **not** 4.5:1 for normal-size text. It is used
as a selection/emphasis **fill**, never as body text, so this is acceptable; the
dark theme's link colour uses the lighter brand "Accent 2" `#FF7A45` (≥ 4.5:1
on the indigo surface). Status colours (amber/green/red) are used as small
dots/legend swatches, not body text; they are paired with a text label, so
colour is never the only signal.

## Keyboard reachability

- Every tool has a single-key shortcut (`Tool::shortcut_key`, spec F-601);
  the toolbar button tooltip shows it.
- Menu commands, undo/redo (`Ctrl+Z`/`Ctrl+Y`), save (`Ctrl+S`), page
  navigation (`Page Up`/`Page Down`), Esc/Del are all bound in `logic()`.
- egui focus/tab navigation is enabled for the shell; text fields and combos
  take keyboard focus normally.
- The canvas is a pointer surface by design (drawing and hit-testing); the
  Inspector provides the same properties as focusable widgets, so any markup
  attribute can be edited without the pointer.

## Names and tooltips

Icon-only controls carry a descriptive tooltip so their purpose is not conveyed
by the glyph alone: layer visibility/lock and reorder (▲/▼), and the page
navigation arrows (◀/▶, whose label reads “Page n/N”).

## Remaining limitations (tracked)

- **Automated visual evidence (guide II.27.12).** Rendering real widgets to PNG
  under `egui_kittest` needs a `Host`/plain-`Ui` seam in `RubricApp`. Tracked as
  gap G4 in `docs/guide-compliance.md`; deferred to v0.3.
- **Screen-reader activation on Linux.** egui uses AccessKit; on Linux this
  depends on AT-SPI being present at runtime. No platform-specific glue is
  shipped.
- **Full a11y-tree audit.** A widget-by-widget AccessKit tree dump is not yet
  asserted in CI; the contrast audit is the machine-checked part of this pass.
