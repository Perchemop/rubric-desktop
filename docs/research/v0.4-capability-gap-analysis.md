# v0.4 capability-gap analysis — Rubric vs its paid inspirations

Date: 2026-11-01 · Method: code-verified parity review (every claim checked
against the repo), cross-checked against public product documentation.
Capability-level only; no trade dress, wording or assets copied.

## Basis

Rubric's own 52 feature IDs are done and honestly tracked
(`docs/spec/README.md`, `docs/parity.md`). The gap to Bluebeam Revu / Adobe
Acrobat is not bugs — it is the **second half of each capability**: markups that
can't be reshaped, selections that can't be multiplied, statuses that can't be
batch-applied, tools that can't be saved, and results that can't leave as a PDF.

## Ranked "feels unfinished" gaps (each one small slice)

1. **No path from markups back to a PDF** — build the planned `lopdf` slice as
   *Flatten Page → PDF* (`data/export.rs::write_pdf`), then per-page export.
2. **No multi-select** — shift-click toggles in the click handler (domain
   `delete_selected`/`apply_style_to` already take id sets); then marquee, then
   Ctrl+A.
3. **Status only via Inspector, one at a time** — `EditorAction::SetStatus`
   through the existing one-executor pattern; context menu + Markups List rows +
   Shift+1–4.
4. **No drag calibration** — `Tool::Calibrate`: two clicks capture a segment,
   modal pre-fills the measured length, reuse `Scale` write path.
5. **No resize/vertex editing** — hit-test the already-painted corner handles;
   domain `resize_bounds(corner, pt)`; then segment endpoints, then vertices.
6. **No duplicate/copy/paste** — `EditorAction::Duplicate` + Ctrl+D / Ctrl+V
   (+10 pt offset), one snapshot, count renumbering already handled.
7. **Reusable tools invisible** — left-panel "My Tools" over
   `StylePresetLibrary`; apply-at-creation hook in `finish_markup`.
8. **Markups List is a report, not a console** — inline status per row,
   measurement totals footer, CSV of the filtered view.
9. **Squiggly/underline/strikeout/cloud don't look real** — scalloped cloud
   path (painter math); then PDFium text extraction to anchor text markups to
   real line rects; then find bar.
10. **No PDF summary report** — CSV writer first, then paginated PDF via lopdf.
11. **Legend can't be placed on the page** — `MarkupKind::Legend` rendered at
    paint time from live counts.
12. **Stamps are five fixed strings** — custom text stamp, then `%DATE%`
    tokens, then image stamps.
13. **No live measurement feedback / ortho / snap-to-endpoints** — in-progress
    value badge, Shift = ortho/45°, snap to markup endpoints.
14. **Silent 1:1 on unscaled pages** — prompt for scale on first measure
    (reuse the calibration dialog, "don't ask again" pref).
15. **First-run palette + navigation chrome** — default-open tool groups,
    `MarkupKind::glyph()` icons on buttons, page-number entry box, empty-state
    welcome panel.

## Verdict (blunt)

A paying Bluebeam or Acrobat user doing a real plan review in Rubric today hits
a wall inside the first five minutes. Highlights are drawn as bands over an
empty rectangle rather than on text; selection handles are paint, not grips (a
rectangle drawn 10 px short must be deleted and redrawn); there is no
shift-click, no duplicate, and setting thirty punch statuses means thirty
Inspector detours while the genuinely good Markups List sits read-only;
calibration demands a typed ratio instead of a dragged known distance and
unscaled pages measure 1:1 silently; and at the end there is no PDF to hand
back — the deliverable is a sidecar JSON and a per-page PNG. What *does*
impress: the sidecar architecture, real layers, scale-aware measurements,
honest undo and a strong filterable list — the bones are professional, but the
workflow half that makes the paid tools feel finished is exactly the half that
is missing.

**Conclusion: Rubric is a promising markup editor; the inspirations are markup
workflows. v0.4 closes the workflow half (gaps 1–8 first).**
