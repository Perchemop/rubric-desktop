# Rubric full-app audit (v0.3 line, `main` as of 2026-11-01)

Method: ten parallel read-only audits over the whole application (menus &
commands, toolbar & tool model, inspector, canvas, app shell & panels, data
layer, domain layer, documentation & links), one code-verified capability-parity
review against the paid inspirations, and one free-design-tooling research pass.
No local toolchain runs (cargo is CI-only per `AGENTS.md`); every compile/clippy/
test/release verdict below is therefore **pending CI confirmation**.

Scope: `apps/rubric` (all of `src/ui`, `src/domain`, `src/data`), `crates/*`
(usage), CI packaging workflows, and the tracked documentation. Findings carry
file:line evidence from the audited tree; several have since been fixed on
branches (noted inline).

**Headline: 3 blockers, 27 majors, ~30 minors, ~20 polish items.** The
application's bones are professional — a pure, serde-safe domain, honest
one-snapshot undo discipline, a strong filterable Markups List — but three
blockers can destroy or mis-state user data, and the *workflow* half that makes
the paid inspirations feel finished (multi-select, resize, batch status,
calibrate-by-gesture, export back to PDF) is missing.

## 3. Minors (selected, by area)

- **Domain:** `remove_page` silently destroys/re-points markups on later pages; `MeasurePerimeter` ignores the `closed` flag; mismatched kind/geometry stores a zero measurement; text hit box assumes a fixed 16 pt line height vs user-settable `font_size`; `ruler_ticks` can overshoot the range end and has no iteration cap; diff is blind to layer moves; `StylePreset::apply_to` copies `locked` and ignores target locks; `Markup::summary()` always reports raw points; ASCII-only case folding in list filters. — *all assigned to the domain fix agent*
- **Toolbar/palette:** hidden default layer accepts creation (invisible committed markups); Polyline grouping disagrees across three sources; three divergent tool-selection paths; hardcoded group arrays ignore `MarkupKind::group()`; the active tool is invisible when its group is collapsed; domain glyphs unused; no shortcut legend; no tool search. — *v0.3 follow-up + polish*
- **Shell:** Markups List status text fails WCAG AA on the light theme (AMBER ≈ 1.9:1); the list is a non-virtualised `egui::Grid`; thumbnails decode synchronously on the UI thread and transient failures are poisoned; workspace state (panel visibility, filters, zoom, page) is not persisted; quit confirm lacks "Save and Quit"; export-report dialog mishandles cancel; update-mutex; `Icon` fallback paints a sparse stripe pattern while its comment claims a solid tile. — *follow-up slices*
- **Data:** `save_project` leaked `.tmp` on write/fsync failure; encrypted PDFs surface as pretty-Debug dumps; render-cache writes non-atomic and never pruned; hayro `u16` pixmap ceiling unclamped; PDFium discovery omits the exe-dir `lib/` subdir the docs promise; schema guard runs after the typed parse; the hayro build still compiles `pdfium-render`. — *data agent / follow-ups*

## 4. Polish highlights

Ellipsis inconsistency; zoom actions leave the menu open with no status; note popover is a fixed 220×160 box with no scroll/clipping/flip; preview style doesn't match the committed stroke; rulers float with the page and show only raw points; dead `DrawState::Count`/`InspectorMode`/`tools_for_group`; status dots and handles scale with zoom while their offsets don't; window title never shows an unsaved marker; comment timestamps show time-of-day only; per-frame `painter.layout` clones (partly fixed on the canvas branch).

## 5. Capability parity — the honest answer

Full analysis: `docs/research/v0.4-capability-gap-analysis.md`. Summary of the
parity verdict:

> A paying Bluebeam or Acrobat user doing a real plan review in Rubric today
> hits a wall inside the first five minutes. Highlights are drawn as bands over
> an empty rectangle rather than on text; selection handles are paint, not
> grips; there is no shift-click, no duplicate, and thirty punch statuses means
> thirty Inspector detours while the good Markups List sits read-only;
> calibration demands a typed ratio instead of a dragged known distance, and
> unscaled pages measure 1:1 silently; and at the end there is no PDF to hand
> back.

**Answer to "does Rubric look and feel like its paid counterparts?" — No.** The
52 in-scope feature IDs are done and honestly tracked, but the *workflow* half
is missing. v0.4 exists to close it (ranked gaps 1-8 first: flatten-to-PDF,
multi-select, batch status, drag calibration, resize grips, duplicate/copy-
paste, tool-chest UI, an editable Markups List console).
