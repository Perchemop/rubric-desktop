# Rubric v0.2.0 — Full GUI + End-to-End Audit

Date: 2026-10-30/31
Scope: the released v0.2.0 (`main` `fea7e16`, tag `v0.2.0`).
Method: six read-only per-requirement code audits (one per requirement group,
run in parallel), a live GUI audit on the primary platform (Linux aarch64 /
Crostini, driven with `xdotool` + X11 capture), and firsthand verification of
the highest-severity findings. No builds were run (cargo is banned locally).

**Headline:** the feature set is present and the domain maths is largely
correct, but the release has **9 functional defects** that a real user will hit,
several of them on the flagship "review" workflows. The v0.2.0 binaries also
self-report version **0.1.0** because the crate version was never bumped.

---

## 1. Critical / high-severity defects (BROKEN)

| # | Area | Defect | Evidence |
|---|---|---|---|
| H1 | Release | **Crate version never bumped.** `apps/rubric/Cargo.toml:3` is `version = "0.1.0"` while the tag is `v0.2.0`. Every v0.2.0 binary reports 0.1.0 at runtime, so Help ▸ Check for Updates says "A newer release is available: v0.2.0 (running 0.1.0)" on the *latest* build. | `apps/rubric/Cargo.toml:3`; `crates/*/Cargo.toml:3`; live update-check message |
| H2 | Measurements | **Display-unit switch is a no-op; it silently changes the physical meaning.** The `ComboBox` writes the new unit straight into `scale.unit` (`inspector.rs:289`), then calls `scale.with_display_unit(new_unit)` on a scale that *already* holds the new unit (`inspector.rs:295-299`), so the conversion is `upp·ppu(u)/ppu(u)` = identity. Switching a page from feet to metres turns a `100 ft` reading into `100 m` (×3.28 physical change). The domain helper is correct and unit-tested; only the call site is wrong. | `ui/inspector.rs:289,295-299`; `domain/units.rs:124-127` |
| H3 | Measurements | **Count markers are hard-coded to "1"; the count tool is useless.** The only construction site sets `MarkupGeometry::Count { at: pp, number: 1 }` (`canvas.rs:1166`). No increment, renumber, or total anywhere. Every marker draws `1` and `1 count`. `DrawState::Count` is never constructed. | `ui/canvas.rs:1166`; `domain/markup.rs:682,691` |
| H4 | Markups | **Strikeout / underline / squiggly render as plain rectangles.** Domain kinds + defaults exist, but the canvas routes them through the generic `Bounds` arm (`canvas.rs:1170-1172`) and draws a plain rect (`canvas.rs:260-270`). Three visible tools advertise behaviour the renderer never implements (also affects PNG export). | `ui/canvas.rs:1170-1172,260-270` |
| H5 | Review | **Status / author / subject / stroke edits are not undoable and do not mark the project dirty.** The inspector applies these to the in-memory markup but never sets `committed`, so no undo snapshot is pushed and `dirty` stays false (`inspector.rs:415-448,504-517`; shell at `app.rs:1488-1495`). Ctrl+Z will not revert them and autosave will not persist them unless another committed action happens. | `ui/inspector.rs:415-517`; `ui/app.rs:1488-1495` |
| H6 | Persistence | **File ▸ Print can silently do nothing.** `print_page` returns `Err` on render or temp-write failure **without** setting a status (`app.rs:762-787`) and the caller discards it (`let _ = self.print_page();` `app.rs:994`). Only the final OS-print failure sets status. | `ui/app.rs:762-787,994` |
| H7 | Navigation | **"Fit Page" does not fit.** It sets `zoom = 1.0; pan = 0` (`app.rs:424-427`); `page_origin` is a fixed constant never recomputed from the viewport. The label is misleading on a live control. | `ui/app.rs:424-427,178` |
| H8 | Packaging | **PDFium is not bundled** (Q-PACK-1): a fresh install cannot import or render a PDF until the user supplies `libpdfium.so`/`pdfium.dll` (the maintainer hit exactly this). | release asset contents; `docs/pdfium.md` |
| H9 | Review | **Project-name / document-title / author edits are not committed either** (same class as H5): they mutate the model but never snapshot/`dirty`. | `ui/inspector.rs:155-177` |

## 3. Low / cosmetic

- **Layout bug (live):** the Markups List filter row **clips the "Subject" filter** ("Subje") at the panel's right edge. `ui/markups_list.rs` filter row (screenshot `22-export-report-dialog.png`).
- Dead code / unused scaffolding: `InspectorMode` (`app.rs:61-69`, passed but ignored at `toolbar.rs:44`), `DrawState::Count` (never built), `toolbar::tools_for_group` (`#[allow(dead_code)]`), `ToolSet.visible/locked` (never read).
- Group-by-status sections sort **alphabetically**, not in the picker/`ReviewStatus::ALL` order.
- "Clear filters" is unconditionally click-enabled and always reports "filters cleared".
- Traceability points at the wrong modules: R-S-004 names `domain/project.rs` (actual layer code is `domain/document.rs`); R-S-015 names `data/export.rs` (actual image path is `data/render.rs`/`print.rs`).
- `Measurement::value_points` doc says "kept for loss-free re-scaling" but re-scaling always recomputes from geometry; it is display-only.

## 4. Test-coverage gaps

- **`History` (undo/redo + the 128 cap) has zero tests**, yet F-604 is marked DONE.
- **`view.rs` (zoom constants/presets) has no tests**; the "no magic numbers" claim is untested.
- **The entire canvas drag-to-draw / preview lifecycle is untested** (`ui/canvas.rs` has no test module).
- **No UI-level test harness** for `canvas.rs`, `toolbar.rs`, `inspector.rs`, `menu.rs`, `app.rs` — every "UI wiring exists" claim here is by source reading only.
- Untested: F-102 (strikeout/underline/squiggly), `Scale::describe()` (M18), perimeter/angle/count recompute, `path_points_ok` commit gate, `delete_selected`.
- PDFium-dependent tests silently **skip** when `RUBRIC_PDFIUM_PATH` is unset, so PDF coverage is conditional.
- The print test (`data/print.rs:100-110`) actually invokes the real OS print path and asserts nothing.

## 5. GUI audit (live, primary platform)

Reachable states were captured on the Crostini X11 session (`import` + `xdotool`):

- **Menus:** File (New/Open/Import PDF/Export Report/Export Page Image/Print/Recent/Save/Save As/Auto-save/Quit), Edit (Undo/Redo/Delete/Clear/Copy/Paste Properties/Order), View (Zoom In/Out/Fit Page, 50/100/200 %, Show Grid, Snap to Grid, Grid Spacing, Theme, Show Markups List), Help (About/Check for Updates/Report a Bug) — all present; Edit-menu enablement is correct for the empty state.
- **Toolbars:** top strip + left groups (Review: Highlight/Strikeout/Underline/Squiggly/Text Box/Callout/Sticky Note/Stamp; Shapes: Rectangle/Ellipse/Cloud/Polygon/Polyline; Paths: Line/Arrow/Pen; Measure).
- **Inspector:** Status legend (colour swatches + live counts), Layers, Project, Document, Scale — all present.
- **Markups List:** search + status/author/subject/layer filters + sort/group; honest empty state.
- **Dialogs:** Export Report (group-by + txt/JSON), Report a Bug (scrub notice, technical details, browser/token choice) — both wired and honest.
- **Theme:** launched in **dark** — this is the saved `~/.config/rubric/prefs.json` (`{"theme":"dark"}`), not a bug.
- **Layout bug:** "Subject" filter clipped (above).

**Input caveat:** with synthetic X11 events, **widget** clicks work (menus, tool buttons, collapsibles, dialogs) but **canvas** clicks/drags do not register under Crostini's sommelier compositor (hover position updates, but press/drag on the canvas painter produces no markup). A controlled Xvfb attempt could not create a GL window. This is most likely a synthetic-input/sommelier artifact rather than an app defect (the draw/click code audited clean), but it could not be fully confirmed. **A real-mouse smoke test of draw/select/move/measure is recommended before trusting the canvas flows.**

## 6. Release / packaging audit

The v0.2.0 tag's first runs failed and were fixed during this session:
- AppImage: AppStream `metadata-license-missing` / `-invalid` and non-RDNS id → fixed.
- Windows MSI: WiX v4 `Extension`/`WixUI` placement, `rubric.exe` Source path, and empty `$(var.PdfiumDllPath)` → fixed.
- Release-asset scanner: `unzip` backslash-warning abort and the Windows runner home `C:\Users\runneradmin` → fixed.

Residual: **PDFium not bundled** (H8) and **version not bumped** (H1).

## 7. Positive confirmations (verified correct)

- Measurement maths: area scales with `units_per_point²`; radius = ½ diameter; angle via `angle_degrees`; precision clamp + 0–6 dp formatting.
- Report grouping/export: group by Status/Author/Subject, `.txt`/`.json`, honest success/error/cancel.
- Persistence: save/load round-trip, centralised `schema_version` guard (refuses 0 and newer), autosave dirty+interval gate with a 5 s clamp.
- PDFium discovery order (env → exe-dir → system) and read-only PDF handling.
- Accessibility: real WCAG contrast maths + shipped-palette audit test; honest tracked limits.
- Most status messages are gated on real success; no production `unwrap`/`expect` in the data layer.

---

## 8. Recommended remediation order

1. **H1** version bump (blocks a trustworthy release).
2. **H2** unit conversion, **H3** count, **H4** strikeout/underline/squiggly, **H7** Fit Page — headline correctness.
3. **H5/H9** commit status/author/subject/title edits (undo + dirty).
4. **H6** print error surfacing, **H8** bundle PDFium.
5. **M1** save-on-exit prompt; then the remaining medium/low items and the test gaps.
