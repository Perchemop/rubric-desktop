# UI/UX Audit — 2026-11-07

Owner directive: "audit every aspect of a visual or manual feature a user
would use." This file is the consolidated record. Findings were produced by
three parallel review passes over `apps/rubric/src/ui/*`, `main.rs`, and
`USER_GUIDE.md`: a surface inventory, a standards audit (every state designed;
no dead controls; no unstyled controls; accessibility as a gate), and a
capability-level comparison against the products listed in
[`inspiration.md`](inspiration.md). Capability-level inspiration only — no
external implementation material is reproduced here.

Status legend: **Fixed** = landed on `main` in PR #148 · **Queued** = in the
ROADMAP UI-audit queue · **Keep** = verified strength, protected in redesigns.

## P1 — queued (next slices, priority order)

1. **Feedback system** — one unstyled top-right label carries errors,
   confirmations, developer jargon ("Snapshot: …"), raw UUIDs, and gets
   stomped by every subsystem; errors are visually identical to "Ready";
   long messages clip on narrow windows. *Fix direction:* severity-coloured
   status + non-blocking toast layer; dedicated messages instead of
   "Snapshot: …"; "Selected 1 markup" not the UUID.
2. **UI-thread freezes** — page-image export/print (headless render + 150 DPI
   rasterise + blocking `lp`), bug-report submit (blocking HTTP), Highlight
   clicks (re-parses the PDF per click, uncached), page background (sync
   rasterise, documented hitch), page thumbnails (render inline while
   scrolling). *Fix direction:* adopt the app's own worker-thread +
   repaint-signal pattern (the update-check) everywhere.
3. **Inspector tabs are decorative** — five tabs render the same always-on
   section stack with cross-referencing hints; "Selection" tab has no content.
   *Fix direction:* tabs become the sole navigator.
4. **Bates/settings edits spam undo history** — one snapshot per frame while
   typing or dragging. *Fix direction:* commit on `drag_stopped`/`lost_focus`
   like the neighbouring controls already do.
5. **Scroll always zooms** — no plain-scroll pan; trackpad two-finger pan is
   unusable. *Fix direction:* zoom on Ctrl/⌘+scroll (or a setting); plain
   scroll pans.
6. **Tool Chest rows clip** at the default 210 px panel width ("Apply to
   Selection"/"Rename"/"Delete" fall off-panel); "Apply to Selection" vanishes
   instead of disabling with a hint.
7. **Stroke colour edit silently overwrites fill** (including alpha).
8. **No cursor affordances** — no crosshair for draw tools, no move/resize
   cursors, no I-beam in text edit; marquee is near-invisible on dark chrome.
9. **Canvas is an accessibility dead zone** — no AccessKit node, no keyboard
   nudge; page thumbnails have no widget info.
10. **Duplicated tool pickers with divergent grouping** (top strip families vs
    left panel collapsing groups) and a wrong "Measurement:" hint class
    (Paths — hint fixed in #148, duplication remains).
11. **Left-panel collapsing groups start closed** — first-run tool discovery
    is poor while the top bar crams all 25 tools into wrapped rows.
12. **Opening a project resets workspace prefs** (`UiState::default()`
    discards panel visibility/zoom loaded from prefs); `show_pages`,
    `focus_mode`, `show_minimap` saved but never restored; `ui_scale` has no
    UI control; prefs parse failure silently resets.
13. **Shortcuts dialog is inaccurate** — lists non-existent bindings
    (auto-save toggle, theme cycling, Esc-fullscreen, Ctrl+C/V properties),
    omits the 25 real single-key tool shortcuts; `USER_GUIDE.md` repeats some
    claims and contains editing debris in the Bates section.

## Capability comparison (clean-room summary)

Against the capability checklist gathered from the inspiration products'
public, user-observable behaviour, Rubric already implements the structural
core: the 23-kind annotation taxonomy, non-destructive sidecar storage, a
filterable/sortable/groupable markups table with CSV export, status model
with legend and batch operations, saved style presets with apply/stop arming,
two-point calibration with presets/units/precision, eight measurement types
with live badges, undo/redo with gesture-safe snapshotting, single-key tool
shortcuts, and AccessKit-labelled custom widgets.

The gaps that make it *feel* lesser are workflow-feel gaps, not missing
features — and they map exactly onto the P1 queue above: feedback surfaces
(no severity, no toasts), responsive performance (inline heavy work), the
properties loop (decorative tabs), input conventions (scroll-pan, cursors,
right-click depth), and honest documentation. Closing the P1 list is the
highest-leverage path to the app feeling professional.

## Keep list (verified strengths — protected in redesigns)

1. The async worker pattern in `begin_update_check` — the template for every
   P1 freeze.
2. Unsaved-work protection (OS-close veto; Save-and-Quit only quits if the
   save landed).
3. Drag-snapshot discipline on the canvas (one snapshot per gesture,
   zero-delta guards).
4. Zoom-invariant hit tolerance (screen-budget converted to page units).
5. The theme system itself (tokenised type scale, WCAG-audited palettes with
   tests, real high-contrast mode).
6. The Markups List (pure-domain filter/sort/group, designed empty states,
   CSV export, totals footer).
7. Render-failure poisoning (`failed_page_textures` + `bg_error` dedup).
8. Tool Chest save section (disabled-with-hint buttons done right; rename
   drafts survive frame rebuilds).
9. The single command executor (`pending_action` → one path owns history and
   status; `shortcut_hint` never advertises an unbound binding).
10. The headless a11y rig (kittest over the real shell, committed visual
    baseline, CI round-trip for re-baselines).
